# Рефлексия: chezmoi и цель "одинаковая среда на mac / WSL / голом Linux"

Дата: 2026-07-26.
Повод: аскин попросил изучить репозиторий chezmoi (`~/.local/share/chezmoi`,
origin `git@github.com:AskinNET/dotfiles.git`) и предложить, как его доработать
под три целевые машины: macOS, Windows+WSL2, "голый" Ubuntu/Linux.

## Что уже хорошо

- Секреты — через `age` (публичный ключ в `.chezmoi.toml.tmpl`), плюс интеграция
  с bitwarden/rbw (`unlock = "auto"`). Разумная база для мультимашинности.
- Есть один пример templating по ОС: `dot_config/alacritty/alacritty.toml.tmpl`
  ветвится на `.chezmoi.os` (darwin/linux) для размеров окна и шрифта.
- `run_once_install-zap.sh` — воспроизводимая установка zsh-плагин-менеджера
  без ручных действий.
- `.chezmoiignore` уже осознанно исключает `nvim/lazy-lock.json` — то есть
  прецедент "не всё должно быть одинаковым на всех машинах" уже есть.
- Терминалы (`osc52 = "CopyPaste"` в alacritty, конфиги kitty/rio/tmux) в
  целом кроссплатформенные, без ОС-специфичного мусора внутри.

## Что нашлось не так (с живыми доказательствами из этой сессии)

1. **WSL не отличается от голого Linux.** Везде, где есть ветвление, оно идёт
   по `$OSTYPE`/`.chezmoi.os`, а WSL репортит `linux` — то есть WSL и "чистый
   Ubuntu" сейчас неотличимы для конфигов, хотя по факту у них разное
   окружение (буфер обмена, открытие браузера/файлов, GUI, systemd).
   Ничего не проверяет `/proc/version` или `WSL_DISTRO_NAME`.

2. **Конфиги воспроизводимы, а сами инструменты — нет.** chezmoi аккуратно
   раскладывает конфиги, но нет ни Brewfile, ни apt-списка пакетов, ни
   `run_once_`-скрипта, который на новой машине поставил бы nvim, tmux,
   zoxide, fzf, lazygit, yazi, rio, kitty, cargo и т.д. Сейчас автоматически
   ставится только zap. "Одинаковая среда" на новой машине на деле означает
   "вручную вспомнить и доставить весь тулинг по памяти".

3. **Различия между машинами зашиты как raw-строки, а не как данные chezmoi.**
   Пример — `dot_zshrc`: `if [[ "$HOST" == "pcu000" ]]` включает rbw/SSH-agent
   только для конкретного хоста. Чтобы завести новую рабочую машину, придётся
   лезть править shell-логику внутри дотфайла, а не декларативные данные
   chezmoi (`.chezmoi.toml.tmpl` / `chezmoi init` prompts). Нет `[data]`-блока
   вообще — вся дифференциация не в chezmoi, а в рантайм-проверках shell.

4. **Дрейф уже происходит прямо сейчас, на этой же машине.** `chezmoi status`
   в этой сессии показал: `.zshrc`, `.config/zsh/alias.zsh`,
   `.config/tmux/tmux.conf` — все три помечены `MM` (правки внесены и в
   источник, и напрямую в файл в `$HOME`, независимо друг от друга). `chezmoi
   diff` по tmux.conf показал реальные забытые правки (mouse on, M-1..M-9
   биндинги, потом ещё блок F9-переключателя мыши) — сделанные прямо в
   `~/.config/tmux/tmux.conf`, никогда не занесённые обратно в источник.
   (Уточнение: `dot_config/yazi/*`, которые тоже светились в `chezmoi
   status` как "DA", дрейфом не являются — `yazi`-конфиг исправно
   версионируется в источнике и подключается через
   `dot_config/zsh/dot_p10k_custom.zsh`; "DA" там означало лишь то, что на
   этом конкретном контейнере `~/.config/yazi` ещё не был применён, а не что
   он разошёлся с источником.)

5. **Мусор в самом репозитории.** `.chezmoi.toml.tmpl.bak` — забытая копия
   (отличается только одной закомментированной строкой). Незакоммиченный
   `dot_pk10k_askin.zsh` — фрагмент конфигурации powerlevel10k
   (`POWERLEVEL9K_LEFT_PROMPT_ELEMENTS`), который никто и ничто не сорсит
   (`dot_zshrc` подключает только `~/.p10k.zsh`, не этот файл) — похоже на
   недоделанный merge в `dot_p10k.zsh`.

6. **Битые алиасы.** `zshconfig` указывает на `~/.config/zsh/zshrc` (такого
   пути нет — реальный файл `~/.zshrc`), `aliasconfig` — на
   `~/.config/zsh/custom/alias.zsh` (реальный путь без `custom/`). Похоже на
   наследие от другого фреймворка (oh-my-zsh custom/), оставшееся после
   перехода на zap.

7. **Нет README/bootstrap-документа.** Самый нетривиальный шаг —
   как на новой пустой машине получить приватный age-ключ (и/или разлогиниться
   в rbw/bitwarden) до первого `chezmoi apply`, ведь без этого не
   расшифруются секреты — нигде не описан. Всё держится в голове.

## Что предложить (конкретно, по приоритету)

1. Добавить `[data]` в `.chezmoi.toml.tmpl`, считать WSL явно:
   ```
   {{- $isWSL := and (eq .chezmoi.os "linux") (.chezmoi.kernel.osrelease | lower | contains "microsoft") }}
   [data]
     is_wsl = {{ $isWSL }}
     role   = "{{ promptStringOnce . "role" "роль машины (personal/work)" "personal" }}"
   ```
   и переключить `$HOST == "pcu000"` в `dot_zshrc` на `{{ if eq .role "work" }}`.

2. Добавить осознанную WSL-ветку там, где отличие реально есть (открытие
   ссылок/файлов, возможно `$BROWSER=wslview`), не размазывая её по коду как
   `linux`-кейс.

3. Сделать установку тулинга воспроизводимой: Brewfile для mac + linuxbrew,
   список пакетов apt для голого Ubuntu, подключить через `run_once_` (или
   `run_onchange_`, если список пакетов может обновляться) — чтобы
   `chezmoi init --apply` на новой машине разворачивал не только конфиги, но
   и сами бинари.

4. Написать `docs/BOOTSTRAP.md`: как поставить chezmoi → как восстановить
   age identity → `chezmoi init --apply git@github.com:AskinNET/dotfiles.git`.
   (Этот файл, как и текущий, стоит держать в `.chezmoiignore`, чтобы не
   разворачивался в `$HOME`.)

5. Уборка: удалить `.chezmoi.toml.tmpl.bak`; либо доинтегрировать
   `dot_pk10k_askin.zsh` в `dot_p10k.zsh`, либо удалить; починить `zshconfig`
   и `aliasconfig`; добавить `.config/yazi` (или конкретно
   `flavors`/`plugins`) в `.chezmoiignore`, как уже сделано для
   `lazy-lock.json`.

6. Явно решить судьбу `lazy-lock.json`: либо раскоммитить и версионировать
   (полная воспроизводимость плагинов), либо оставить игнор, но осознанно —
   как компромисс "плагины экспериментальные, версии могут различаться между
   машинами".

7. Взять за привычку: правки в `~/.config/...` вносить через источник chezmoi
   (`chezmoi edit` / правка в `~/.local/share/chezmoi` + `chezmoi apply`), а
   не напрямую в файл в `$HOME` — иначе дрейф из пункта 4 будет повторяться
   на каждой машине. Периодически `chezmoi status`/`chezmoi diff` как чек-ап.

## Мета-вывод

Инфраструктура (age, git, templating-механизм) для мультимашинности уже на
месте и выбрана разумно. Не хватает не инструментов, а дисциплины
использования: различия машин живут в разрозненных raw-проверках вместо
единого `[data]`, установка самого софта не автоматизирована, а часть машин
(минимум эта) уже разошлась с источником незамеченно. Первый практический шаг
— не новые фичи, а закрытие дрейфа (`chezmoi diff` → `chezmoi re-add` или
`chezmoi apply` осознанно) и уборка мусора, а уже потом — WSL-детект и
bootstrap-скрипты.
